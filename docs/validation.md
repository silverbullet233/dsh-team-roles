# Native Gateway refactor validation

Published v0.6.0 was validated on macOS with Node 26.0.0 and the exact official DSH 0.2.2-alpha.2 npm graph. The unreleased 0.6.1 candidate on this branch (not tagged, released or published) was validated on macOS with Node 26.0.0 against the exact official DSH 0.2.2-alpha.3 npm graph, using a locally built archive installed in an isolated native profile. All automated native fixtures use test-owned stores, bounded deterministic adapters and in-memory credential records. No live provider inference was performed.

- Unit regressions: role snapshots, native admission, immutable members, writer locks, create/input retry conflicts and uncertain reply windows, projection evidence and drain-before-disposal.
- Native regressions: same-member follow-up, running queue/steer, Team interruption, configuration edits and cold/process-crash recovery, empty catalog inheritance and independent Web forks.
- Real Node Connection/Gateway over HTTP/Mux: launch-token exchange, role-managed Team creation, duplicate create, processing/result distinction, disconnect without cancellation, fresh API Peer and shutdown guard.
- Exact runtime and release-safety suites; built tarball install/load in a fresh native profile, negative API checks and outside-launcher rejection.
- Browser inspected in Chrome using the ordinary official Web/base and Team bundles. Settings → Team roles created a synthetic Team, Open Team selected that same Session, and the native view showed KEYLESS_WEB_COMPLETE with the configured fixture model.
- Final Chrome acceptance used the companion client's owned instance: native creation returned one Team receipt, Open Team closed Settings and selected its completed Session with NATIVE_OWNED_E2E_COMPLETE, and reload/reopening retained the same disabled request fields and receipt. The Settings dialog had no horizontal overflow. The fixture then shut down successfully through the client's native activity guard.

The Web fixture has a read-only in-memory credential provider and a synthetic model. This certifies the integration path, not paid inference or all user-installed plugin combinations. Host 0.3.0 is incompatible with the new client. Install the built versioned [0.5.0 release asset](https://github.com/silverbullet233/dsh-team-roles/releases/tag/v0.5.0); provider inference remains outside these synthetic checks.

The cross-repository actual-CLI gate also passed with the client candidate: two native role members, same-member follow-up, client disconnect, safe shutdown and persistent cold restart used nine bounded synthetic adapter requests. The final fixture preflights the effective profile before starting and confirmed no persistent credential file. Earlier failed fixture preparation left test-only native browser grant files because an id patch used `name` as if it replaced a module; those isolated processes/homes were stopped and deleted without reading or reusing credential values. No personal profile, provider credential or global runtime was modified.

PR review follow-up passed 109 tests (62 unit, 35 native, 6 runtime, 6 release), build/package checks and fresh native tarball installation with negative capability gates. New regressions cover missing Web workspaces and shutdown refusal for inconsistent snapshots, unresolved role bindings, aborted unloaded children, unmanaged open turns/shared tasks and changing projections. The updated host also passed the companion client's actual official-CLI gate with nine bounded calls, two role members, same-member follow-up, disconnect and durable restart; no persistent credential file was created.

Release v0.5.0 points to merged commit `c6af666df3657017b5e8293db16d89ad22edb6bd`. Its tag-push [Release package workflow](https://github.com/silverbullet233/dsh-team-roles/actions/runs/41218229003) passed. The actual workflow archive was checksum-verified and installed/loaded in a fresh keyless native profile before publication; its SHA-256 is `e9f89b9e93e0c236005d3ad60c78ade3a548ba38f4b9b881bb9fb6378b5f5d61`. Publication preserved the verified asset digests.

## Restricted-environment candidate gate

Run `npm run build && npm run test:isolated` for synthetic data-service, admission, role, runtime and release checks without listeners, process identity probes or real credentials. This explicitly excludes `test/native/gateway.test.mjs`, `test/native/lifecycle-composition.test.mjs` and the socket-based flushed-process-crash case in `shared-session.test.mjs`. The shared-session data tests run in a separate batch after a larger parallel native invocation stopped making progress; the cause of that incomplete run is not established. Both baseline and candidate shared-session data tests passed separately (16 each). It includes the exact permission-profile/member-inheritance regression against native in-process data services. Synthetic Ed25519 testing belongs to the companion client and does not create a production trust authority.

During this change, the broader socket gate encountered `listen EPERM` in the local sandbox and was stopped; it was not accepted as passing. Real MCP/host startup, ps-based attribution, retained-process reuse and shutdown, browser/Connection socket integration, supervisor/Codex effective-limit acquisition and inherited OS/network enforcement remain separate acceptance gates. No process-identity guard or security setting was changed to make tests pass.
