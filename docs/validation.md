# Full-access default validation — 2026-11-08

Current behavior: the companion starts native DSH directly with `danger-full-access`/`never` and network enabled intent, without automatic Codex metadata inheritance. Explicit profiles/attestation, admission guards, policy propagation and attributed lifecycle protection remain. Outer OS/process/admin restrictions remain effective. The former launcher/bootstrap/boundary-probe implementation has been removed from the client.

Use `npm run build`, `npm run test:isolated` and `npm run pack:check` for the restricted-environment gate, then normal full CI before merge. The isolated gate excludes listener/process-identity tests and is not a full-CI substitute. New full-access-default validation does not rerun paid provider inference or certify unrestricted OS/network access. See [current configuration](configuration.md#candidate-codex-permission-profiles).

## Restricted-environment candidate gate

Run `npm run build && npm run test:isolated` for synthetic data-service, admission, role, runtime and release checks without listeners, process identity probes or real credentials. This explicitly excludes `test/native/gateway.test.mjs`, `test/native/lifecycle-composition.test.mjs` and the socket-based flushed-process-crash case in `shared-session.test.mjs`. All other native files are discovered dynamically and run serially in fresh processes through `scripts/test-native.mjs --isolated`. The full `npm run test:native` uses the same runner with every native file and no skipped cases. Each file has a 45s process deadline and tests have a 30s default deadline; exceeding a deadline fails the gate and reports unrun files. No timeout counts as a pass.

The previous parallel `npm run test:native` in [CI run 42140282110](https://github.com/silverbullet233/dsh-team-roles/actions/runs/42140282110) stopped producing output after build and 142 unit tests passed, then was cancelled in the native stage. Its cancellation initiator and exact stalled native operation were not established. The local old parallel run is also incomplete and is not counted. Serial file execution avoids overlapping timing-sensitive host fixtures and identifies any failing file promptly. This exposed a reproducible native Job observation cleanup hang: starting host disposal before the asynchronous controller-detachment effect settled left teardown waiting. Awaiting detachment fixed the bounded local reproduction, but [CI run 42144700709](https://github.com/silverbullet233/dsh-team-roles/actions/runs/42144700709) still hit the same file's deadline. The test now also waits for the interrupted child's native owner scope to unload (registry removal and inactive roster state); loop idle alone precedes that cleanup. Failure cleanup settles fixture jobs and awaits detachment. Separately, fixture callbacks awaiting unresolved response/request gates ignored the loop AbortSignal, so disposal could wait forever after a test failed or timed out. They now race cancellation; two actual native disposal regressions cover permanently stalled callbacks. These are concrete fixture cleanup fixes, not proof of the old CI stall's exact cause. The full listener/lifecycle gate still requires CI or an environment that permits loopback listening.

Native profile tests cover initial/member/restored policy, passive current-policy snapshots, a profiled parent's ordinary SessionController fork and independent seeded ancestry through cold activation. The pinned SessionController fork itself clears `parentSession`; a separate native seeded Session retains ancestry metadata to exercise the former overbroad hook. Only actual Team membership or native delegation ownership admits member inheritance. Synthetic Ed25519 testing belongs to the companion client and does not create a production trust authority. The companion now consumes experimental Codex sandbox-state and supplies a whole-host official launcher backend; these fixtures verify native profile data and inheritance, not OS confinement. Full-access fallback (danger-full-access/never) and outer-launcher (danger-full-access/ask) projections preserve unknown network and their exact approval policy before member work. Recursive native spawn/fork/empty-fork delegation is checked with both read-only/ask and full-access/never, including cold restoration without policy rewriting. A later real Codex tools/call observation successfully injected metadata; a real read-only candidate host then reached official DSH runCli and failed with OS EPERM writing its profile configuration, before provider inference. This failure cannot trigger fallback. The earlier sandbox_apply failure is separate evidence. At that point, full approval/reviewer and managed-network policy, actual host sandbox availability and real user-session acceptance remained unverified. The scoped acceptance below updates only the exercised host/model path.

During this change, the broader socket gate encountered `listen EPERM` in the local sandbox and was stopped; it was not accepted as passing. Real MCP/host startup, ps-based attribution, retained-process reuse and shutdown, browser/Connection socket integration, supervisor/Codex effective-limit acquisition and inherited OS/network enforcement remain separate acceptance gates. No process-identity guard or security setting was changed to make tests pass.

The first full CI fallback run [42389965185](https://github.com/silverbullet233/dsh-team-roles/actions/runs/42389965185) failed three recursive fixture cases because a consumer flush raced native child disposal and reached an already closed JSONL handle.
