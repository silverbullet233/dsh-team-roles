# Installation migration and rollback

Version 0.3.0 is installed as a built native DSH package rather than a prepared developer checkout. Keep native profile entry id `dsh-agent-team`, protocol 1, existing durable record discriminators and existing state/socket configuration. This preserves member identity, immutable snapshots and bridge idempotency correlations. The Codex client remains independent.

No legacy JSON is required on a fresh installation. The bundle supplies portable deployment defaults and an empty role catalog; Teams remain available and use native main Agent model selection and child inheritance. Configure explicit provider routes in Settings when role policies are wanted. Saving an entirely empty catalog restores native defaults for new Teams; existing managed bindings and existing unmanaged Teams retain their behavior. If `dsh-agent-team.json` already exists under the native Harness home, its values remain inherited initial configuration and are read without modification. A saved profile catalog continues to override it. The native package manager and Settings retain their normal profile/home/CLI precedence and revision/atomic-write handling.

Before replacing an older linked package, preserve the existing nonsecret package/profile configuration using the native workflow and retain its source Git checkpoint. Do not copy credentials or overwrite the Harness home. Check for active managed work and coordinate lifecycle changes. Remove the old native bundle registration before adding the new version; never run both bridges against one writable state directory/socket. Profile changes apply through native HMR when available and may otherwise require a coordinated restart.

The old combined host/client checkpoint is `71e9f7a`; the split protocol-1 native package checkpoints include `a7c4d59` and `fb37277`. Rollback needs the matching native package, profile overrides and client protocol. The stable role bindings remain native data. A profile override whose module-name assertion targets `dsh-team-roles` must be reconciled with the chosen rollback bundle's module name. Do not replace account/session stores.

Development connectors, source installers and source-start helpers are excluded from release archives. Normal tarball installation needs no manual node_modules links, install scripts or provider credential migration. Existing roles are not rewritten when configuring the new package; catalog changes affect future reservations only.
