# Ownership, configuration migration and rollback

`dsh-team-roles` owns the native host; `oh-my-codex` retains the `dsh-agent-team` Codex manifest, skill, thin MCP/CLI client and client tests. The host's native profile entry id stays **`dsh-agent-team`** so existing configuration addresses remain stable. Persistent record discriminators, state directories, socket path and Team/member IDs are unchanged. Package name and repository ownership do not migrate or recreate native account/session data.

The new bundle reads the existing nonsecret JSON at `~/.dsh/dsh-agent-team.json` as inherited initial values. It reads deployment fields independently and maps the legacy role dictionary into `catalog: { leadRole, roles: [{ name, ...role }] }`. Native Settings writes a complete catalog into the active profile (`~/.dsh/profiles/web/cordis.patch.yml` for the installed Web profile). The schema's volatile field updates the existing role service without reloading it. Higher home/CLI overlays retain precedence; native ConfigEditor rejects writes they would override. No auto-import rewrites the old JSON, and no credential file is copied.

A save validates all catalog entries against the current native registry before persistence. The host's Config hook prevents raw Settings writes from bypassing that asynchronous check; use **Settings → Team roles** for role changes. Native Settings owns locking, atomic file replacement, revision conflicts, live application and rollback if reconciliation fails. Editing begins at a fixed revision; stale drafts must be reloaded. Save applies to future reservations only. Once a native member is bound, its role snapshot remains authoritative even after its role is changed or removed.

Before replacing an installation, prepare guarded backups with `scripts/install-native.mjs`; it refuses documents containing embedded secret material. Preserve the old Git checkpoint and verify the new package's tests/build before removing tracked host files from the old repo. Remove the old **native** bundle with the official `dsh plugin --profile web remove dsh-agent-team`, then add `link:/absolute/path/to/dsh-team-roles --ignore-scripts`. This removal does not uninstall the separate Codex plugin. Never activate both native servers against the same socket. Prefer native HMR; coordinate any host restart that could interrupt running work.

Rollback uses the same official package manager: remove native `dsh-team-roles`, restore the old checkout at commit `71e9f7a` (or a separate rollback checkout of it) and add its linked bundle. Restore only the guarded nonsecret profile/package backups if required. The original JSON and state are retained. A new profile entry override whose `name` is `dsh-team-roles` must be removed/restored with the profile backup before the old `dsh-agent-team/host` bundle can load. Protocol 1 clients intentionally reject the old unversioned host; use the matching old client checkpoint for rollback. Do not overwrite `~/.dsh` or account/session stores.

Installation backups live under `~/.dsh/dsh-agent-team/install-backup-<timestamp>/`. Code reconciliation backups use `profile-before-reconcile-<timestamp>.yml`. Backups contain configuration and package metadata only after the nonsecret guard accepts them. The final validation report records the exact backup and installed paths used on this machine.
